Refresh livraison from all five carrier sources, retrieved 2026-10-25: 411 stop-desks to 449.

Previous pull 2026-06-18. Yalidine 199 rows, Guepex 162, Anderson 104 of 116 cards, Noest 102 of 114, Maystro 38 of 44. 16 carriers, 9 with open desks, 63 wilayas from 61. Every one of the 449 records is `geo_precision: exact` / `geo_method: carrier_relay`, as all 411 were: nothing here is approximate, so the sector stays single-precision.

**40 added, 2 removed.** The additions are four months of sources that publish continuously, plus three desks the fetcher had been unable to read at all (below). Both removals were checked against the live page rather than inferred from the diff: `470201` (speedmail, Bounoura) is gone from the Yalidine table and `anderson-33-in-amenas` is gone from Anderson's directory.

**Ids follow places.** A carded id is minted from the card's own title, so when Anderson retitled "Sidi Abdellah" to "Sidi Abdellah - Zeralda" the same desk, 24 m away, would have retired `anderson-16-sidi-abdellah` and minted a new id. A new id that lands within 100 m of a disappeared one, same operator and same declared wilaya, now takes that id back, nearest pairing first so the outcome never depends on the order a carrier lists its cards in. A committed desk carries the wilaya its coordinate resolved to, so for the nine carded desks in wilayas the 2026 reform created (`anderson-5-barika` ships `60` against a card still printing 05) "same declared wilaya" reads a reform code as agreeing with the card; comparing the two literally would retire exactly those nine ids on a rename. A card that prints no wilaya badge at all (Maystro prints one only inside its own coverage list) is matched on the 100 m radius alone, which was the test deciding in any case. `anderson-16-sidi-abdellah` keeps its id, and no id in this release changed hands.

**Three desks the fetcher could not previously read are now published.** `noest-14c` (Ksar Chellala) links `google.com/maps?q=35.2121,2.3166` directly, a form the link matcher did not recognise, so the card was skipped entirely. `anderson-8-bechar` links a Maps place by cid alone (`?cid=6725298475309267754`), which names a place without stating where it is; that place's pin is committed with its provenance in `scripts/maps-cid-pins.json` and consulted only as a fallback, so a live resolution always wins. Both are the operator's own pin, so both are `exact`.

**Two desks kept the coordinate they already shipped** because their Maps link would not resolve: `anderson-25-ali-mendjeli`, whose link is now a Plus Code place carrying no coordinate, and `noest-19b` (El Eulma). Before this change they were dropped, which deletes a stop-desk that is still published and retires its id over one failed request.

**Four Noest cards link a pin in the wrong wilaya, and all four are omitted.** Each one's Maps link resolves into the area of a *different* Noest desk, so the wilaya cross-check refuses it, and none of the four has an earlier committed coordinate to fall back on. 27B (Mostaganem) links the identical URL to 30B (Ouargla), which can only be right for one of them: the check keeps it for 30B, whose card wilaya matches the pin, and refuses it for 27B. 15C (Tizi Ouzou, Draa Ben Khedda) resolves to 27.8775, -0.2902, which is 1.1 km from `noest-01a` in Adrar. 26A (Medea) resolves to 36.3514, 6.6038, which is in Constantine, 4.5 km from `noest-25a`. 55A (Touggourt) resolves to 27.1980, 2.4787, which is in In Salah, 420 m from `noest-53a`. The run log now names every one of them with the wilaya it declared, the wilaya its pin fell in and that pin's coordinate, and no longer truncates the list at six. A card whose pin lands in a wilaya other than the one it declares is now dropped outright: the card and the link contradict each other, the run cannot tell which is right, and re-shipping the point the desk published last quarter would present a stale coordinate as this run's verified one. The desk comes back by itself on the run after the link is fixed.

The remaining omissions are cards this run could not place at all, and the log now separates the two reasons, because the fix for each is different. Four Noest cards publish no Maps link whatsoever (03B Aflou, 21B Azzaba, 31D Arzew, 43B Chelghoum Laid): those can only come back when Noest adds a link.
